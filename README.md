# Tripster Price Monitor

Автоматический мониторинг цен экскурсий на Tripster с уведомлениями в Telegram.

Работает на **GitHub Actions** — полностью бесплатно, без расхода кредитов.

## Отслеживаемые экскурсии

1. Всё включено: магия Чёрного и Чарынского каньонов, экзотика озёр Кольсай и Каинды (51192)
2. Природа Казахстана: 5 лучших мест за 1 день из Алматы (57434)
3. Комфорт-маршрут по озёрам Каинды, Кольсай и Чарынскому каньону (96862)
4. Озёра Каинды и Кольсай, Черный и Чарынский каньоны — все сокровища Алматы (51584)
5. Топ-локации Казахстана: степи, скалы и горные озёра. Поездка из Алматы (85543)

## Частота проверки

Каждые 15 минут

## Настройка

### 1. Добавить Telegram токен и Chat ID

1. Перейдите в Settings → Secrets and variables → Actions
2. Нажмите "New repository secret"
3. Добавьте два секрета:
   - `TELEGRAM_BOT_TOKEN` — токен вашего бота
   - `TELEGRAM_CHAT_ID` — ваш Chat ID

### 2. Готово!

Мониторинг автоматически запустится в течение часа. Вы получите сводку в Telegram, и затем уведомления при каждом изменении цены.

## Как добавить/удалить экскурсию

Отредактируйте список `EXCURSIONS` в файле `monitor.py`:

```python
EXCURSIONS = [
    {"id": 51192, "title": "Название экскурсии"},
    # Добавьте новые...
]
```

Затем сделайте commit и push.

## Логи

Логи выполнения можно смотреть в Actions → Tripster Price Monitor → последний запуск.


## Контроль завершения и восстановление

Рабочий запуск использует safe_monitor.py. Список экскурсий и формат уведомлений
берутся из monitor.py. Два существующих Telegram secrets сохраняются; GitHub
предоставляет встроенный токен только для этого репозитория. Старый GH_PAT
для нового workflow не нужен.

Очередь tripster-task-7 выполняет один полный процесс за раз. Перед каждым
сообщением резерв доставки атомарно сохраняется в data/watchdog/runtime.json.
При неизвестном результате отправки повтор блокируется, включая очередные
запуски по расписанию. Ошибки чтения не стирают прежние цены.

Отдельный save job сохраняет immutable artifact с prices.json,
sent_notifications.json и служебными отметками выполнения. Если запись в main
не удалась, внешний контролёр может повторить только save с тем же artifact.
Подтверждение data/watchdog/completed.json создаётся только после проверки всех
экскурсий и завершения доставки. Пропуск API или ошибка Telegram завершают сбор
с ошибкой; ложного зелёного результата больше нет.

Уже недоступная экскурсия считается проверенной только при подтверждённом
404/410 самой страницы и API. Её последняя цена сохраняется. Ошибка API при
работающей странице не считается успешной проверкой.

Проверки безопасности: python -m unittest test_safe_monitor -v.
